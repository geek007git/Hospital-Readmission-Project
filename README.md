# CareSync

A patient readmission analytics workspace built around the project's 3,000-record hospital dataset. The interface uses a forest-green sidebar, a light canvas, restrained risk colors, and responsive layouts.

## Run locally

Install Node.js, then run from this directory:

```sh
npm run dev
```

Open **http://localhost:3000**. No package installation is needed to run the dashboard. The included local server serves the dashboard and its CSV; opening the HTML file directly will not load the dataset.

## Workspace

- **Overview:** cohort metrics, observed 30-day readmission trends, risk distribution, prioritized patients, and department comparisons. Trend points expose their discharge and readmission counts on hover or keyboard focus.
- **Patients:** search by patient ID, diagnosis, hospital, or department; filter risk levels; sort and paginate through every matching record.
- **Risk analytics:** diagnosis and age-group risk, length of stay by risk level, and departmental outcomes.
- **Care reviews:** patient details, encounter history, recorded vitals, review notes, and a local reviewed/pending queue.
- **Reports:** a descriptive cohort report, with a print layout for printing or saving as PDF.
- **Data assistant:** common questions are answered directly from the selected dataset. Additional questions use the existing `/api/chat` endpoint when available.
- **Preferences:** table density and page size, saved in this browser.

Hospital and discharge-period filters apply across the workspace. The latest 6/12 month options are relative to the latest discharge in the dataset, rather than today's date. CSV exports include all matching records, including patient search/risk filters or the selected review queue, rather than just the visible page.

Patient records come from the source CSV. Reviews and notes are stored in this browser's local storage; they do not update a hospital system or authorize a discharge. Risk scores are supplied values, not new predictions generated by the dashboard. The recorded readmission rate and the average estimated risk score are calculated separately.

## Deployment and connected assistant

The existing `vercel.json` serves the dashboard at `/` and the serverless function at `/api/chat`. Configure `OPENROUTER_API_KEY` in the Vercel environment to enable the connected assistant, then use `vercel dev` or deploy with Vercel.

The assistant sends aggregate cohort summaries to the server. Its local answers work without an API key. The dependency-free local server deliberately returns an unavailable response for connected assistant requests, which the interface handles with a useful fallback.

## Validation

```sh
npm run check
```

For browser integration checks, install the development dependency and Chromium, start the local server, and run:

```sh
npm install
npx playwright install chromium
npm run test:ui
```

Checks cover dataset totals, chart controls, review persistence, search, sorting, pagination, export contents, cohort filters, reports, assistant fallback and response sanitization, saved preferences, keyboard controls, error recovery, and all seven views at five viewport widths. Screenshots are written to the ignored `.ui-artifacts/` directory. Set `DASHBOARD_URL` to test another local server address.

## Project structure

```text
dashboard/             HTML, CSS, and browser JavaScript
api/chat.js            Existing Vercel/OpenRouter assistant endpoint
scripts/dev-server.cjs  Dependency-free local development server
scripts/verify-ui.cjs   Browser integration checks
hospital_readmission_fhir.csv
train_model.py         Separate model training workflow
ml_output/             Model outputs and benchmarks
```

The frontend uses native SVG charts and icons, native dialogs, and a small CSV parser. It does not depend on external JavaScript CDNs. DM Sans is loaded from Google Fonts when available, with system font fallbacks.
